# Mode d'emploi et hiérarchie des sources

## Ordre de priorité
1. Dernières décisions explicites du créateur consignées dans `01_SPECIFICATIONS`.
2. État vérifié du dépôt GitHub et de ses scripts de génération (fait technique, pas autorité créative).
3. Mission finale GitHub `RECUPERATION_PROJET/sources_validees/MISSION_FINALE_V1.md` pour les éléments non modifiés depuis.
4. `RECETTE_FINALE_COMPLETE...` pour la qualité et les tests.
5. Dossier de transmission du 20 octobre pour les biographies et les chapitres.
6. Documents plus anciens : historiques, ne rétablir aucune décision supplantée.

Un état GitHub plus ancien peut être contradictoire avec le nouveau scénario : marquer « non implémenté », pas « validé et présent ». Les textes de ce pack sont une consolidation, pas une preuve d'implémentation.

## Pour l'utilisateur
Ouvrir Codex avec accès au dépôt `JusteYoann/Pokemon-Yokai-Watch` et à la branche `dev/reconstruction-finalisation`. Joindre ce dossier (ou copier les fichiers dans un répertoire `docs/mission-codex/` du dépôt) puis coller le contenu de `PROMPT_CODEX_A_COPIER.md`. **Aucun fichier du dépôt n'a été modifié lors de la création de ce pack.**

`README.md` indique une version de développement, non finale. `QA_RECETTE_FINALE/VERSION_1_DEVELOPPEMENT/README.md` rapporte 13/15 OST activées dans le profil privé, 354 scripts d'animations/1448 cas mGBA, 1850 chaînes harmonisées, français incomplet, tests ciblés mais pas de traversée complète, 151 obtentions non validées de bout en bout. Le rapport identifie explicitement des blocages avant v1.0. Ce sont des affirmations du dépôt consulté, pas des tests indépendants exécutés pour ce pack.

Ne pas confondre le chemin privé de ROM décrit dans le rapport avec un fichier accessible dans Codex; ne pas demander de publier cette ROM sur GitHub.
